# AcmeCloud Support Escalation Policy

## Purpose

This policy defines situations in which a support issue should be escalated rather than resolved solely by the frontline support agent.

## Escalate When

A support agent should consider human escalation when:

- The available knowledge is insufficient to determine a safe resolution.
- A production service appears degraded.
- Multiple customers report the same technical issue.
- There is a potential security incident.
- A requested action requires elevated permissions.
- The recommended resolution could cause significant customer impact.
- The support agent cannot verify the required system state.

## High-Priority Incidents

Issues affecting production availability, authentication across multiple customers, significant API failures, or potential security incidents should receive urgent review according to the applicable incident-management process.

## Customer Communication

Support responses should clearly distinguish between:

- Confirmed facts.
- Information currently being investigated.
- Recommended next steps.

Support agents must not claim that an action has been completed unless the action was actually performed through an authorized system.

## Human Review

When knowledge or system information is insufficient to safely determine the correct action, the ticket should be escalated to an appropriate human team rather than relying on an unsupported AI-generated conclusion.
